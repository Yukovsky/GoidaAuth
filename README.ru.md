## Как работает авторизация

Проверка лицензии происходит на **прокси** — это единственное место в offline-mode сети, где вообще возможно настоящее рукопожатие с Mojang. Бэкенд затем определяет результат по UUID соединения.

```
Игрок подключается к прокси Velocity (GoidaAuthVelocity)
│
├─ БД: premium = true  → forceOnlineMode  → рукопожатие с Mojang на прокси
│                                             → самозванец не проходит и кикается там же
├─ БД: premium = false → forceOfflineMode
└─ Ник неизвестен      → forceOfflineMode (или online, см. force-online-new-premium)
                       ↓
                бэкенд (этот мод)
                       │
   ┌───────────────────┴─────────────────────┐
   │ UUID ≠ офлайн-UUID → лицензия проверена │
   └───────────────────┬─────────────────────┘
                       │
├─ проверен + premium в БД     → ✅ вход без пароля
├─ проверен + ник неизвестен   → ✅ регистрируется как лицензионный
├─ НЕ проверен + premium в БД  → ❌ кик (самозванец на лицензионном нике)
└─ всё остальное               → /login <пароль>  ·  /register <пароль> <пароль>
                                  ├─ либо автовход по сессии (тот же IP, не истекла)
                                  └─ ник свободен (нет записи в БД) → /premium вместо /register
                                     (лицензионный игрок сразу помечает себя, без пароля)

затем, одинаково для всех → /rules → /acceptrules → игра
```

**Почему UUID, а не свойства профиля.** Velocity выдаёт настоящий UUID Mojang после онлайн-рукопожатия и производный офлайн-UUID (`MD5("OfflinePlayer:" + ник)`) во всех остальных случаях, и клиент не может выбрать, какой ему достанется. Подписанное свойство `textures` не доказывает ничего: скин-плагины вроде SkinsRestorer ставят настоящие подписанные Mojang текстуры пиратским игрокам.

## Режимы развёртывания

|  | **Автономно** | **За Velocity** |
|---|---|---|
| Проверка лицензии | Нет — все игроки входят по паролю | Прокси делает рукопожатие, бэкенд проверяет пересланный UUID |
| База данных | Встроенная H2 · без настройки · в составе jar | Общая MySQL / MariaDB с GoidaAuthVelocity |
| Дополнительно | Ничего | [GoidaAuthVelocity](https://github.com/Yukovsky/GoidaAuthVelocity) на прокси |
| Подходит для | Одиночного сервера | Сети серверов за прокси |

Работают оба режима, но автовход по лицензии существует **только** за прокси. Можно начать автономно, а позже перейти, переключив `database.mode` на `mysql` и поставив плагин на прокси.

## Возможности

<table>
<tr><th>Категория</th><th>Описание</th></tr>
<tr><td><b>Автовход по лицензии</b></td><td>Сессия Mojang проверяется на прокси, а на бэкенде подтверждается пересланным UUID. Самозванцы на лицензионном нике кикаются.</td></tr>
<tr><td><b>Регистрация пиратов</b></td><td><code>/register &lt;пароль&gt; &lt;пароль&gt;</code> и <code>/login &lt;пароль&gt;</code> через Brigadier, с алиасами <code>/reg</code> и <code>/l</code>.</td></tr>
<tr><td><b>Автовход по сессии</b></td><td>Пиратские игроки пропускают пароль при повторном заходе, если совпадает IP и сессия не истекла (по желанию, по умолчанию выключено).</td></tr>
<tr><td><b>Блокировка до входа</b></td><td>Фиксация позиции, слепота, замедление 255, неуязвимость и полная блокировка чата, команд и инвентаря до авторизации.</td></tr>
<tr><td><b>Барьер правил</b></td><td><code>/rules</code> + <code>/acceptrules</code> — одинаковый барьер для лицензионных и пиратских игроков, спрашивается один раз на аккаунт и запоминается.</td></tr>
<tr><td><b>Хеширование паролей</b></td><td>BCrypt (cost 12). Старые хеши PBKDF2-SHA256 проверяются и прозрачно обновляются при следующем входе.</td></tr>
<tr><td><b>Защита от перебора</b></td><td>Блокировка адреса за серию неверных паролей, переживающая переподключение. Ключ — адрес, а не аккаунт, поэтому лишить игрока входа в его собственный аккаунт невозможно.</td></tr>
<tr><td><b>Журнал попыток</b></td><td><code>/attempts</code> — неудачные входы пишутся в отдельную таблицу с аккаунтом, адресом, UUID и причиной, чтобы видеть, кто лезет в чужие аккаунты. Хранится скользящим окном на аккаунт, без плановых чисток.</td></tr>
<tr><td><b>База данных</b></td><td>Встроенная H2 (по умолчанию, в составе jar) либо MySQL / MariaDB для работы за прокси.</td></tr>
<tr><td><b>Защита от твинков</b></td><td>Блокировка мультиаккаунтов по IP или аппаратному отпечатку (HWID требует клиентского мода).</td></tr>
<tr><td><b>Перенос аккаунта</b></td><td><code>/transferaccount</code> — переносит игровые данные, статистику, достижения и сопутствующие файлы между аккаунтами.</td></tr>
<tr><td><b>Правила сервера</b></td><td>Настраиваемые разделы правил и ссылки из <code>config/goida_rules.json</code>.</td></tr>
<tr><td><b>Совместимость с LuckPerms</b></td><td>Отложенная доставка события входа, чтобы обойти гонку инициализации NeoForge и LuckPerms при заходе.</td></tr>
</table>

## Требования

| | |
|---|---|
| Minecraft | 1.21.1 |
| NeoForge | 21.1.193 или новее |
| Java | 21 |
| Сторона | **Только сервер** |
| `server.properties` | `online-mode=false` |

> При `online-mode=true` NeoForge проверяет лицензию сам — мод в этом случае не нужен.

> [!IMPORTANT]
> За прокси обязательно задайте `player-info-forwarding-mode = "modern"` в `velocity.toml` и закройте порт бэкенда файрволом, оставив доступ только через прокси. Режим `modern` подписывает пересылаемый профиль общим секретом; при `legacy`, `none` или открытом порте бэкенда кто угодно может подключиться с любым ником и UUID, и никакая проверка на бэкенде уже не поможет.

## Установка

1. Скачайте свежий `.jar` из раздела [релизов](https://github.com/Yukovsky/GoidaAuth/releases).
2. Положите его в папку `mods/` на сервере.
3. Запустите сервер — конфиг создастся в `config/goidaauth-common.toml`.
4. Убедитесь, что в `server.properties` стоит `online-mode=false`. Больше ничего менять не нужно.

## Настройка

`config/goidaauth-common.toml` — создаётся при первом запуске.

```toml
[database]
  mode = "h2"           # h2 | mysql | mariadb
  host = "127.0.0.1"
  port = 3306
  database = "goidaauth"
  user = "goidaauth_rw"
  password = ""

[login]
  timeout_seconds = 60
  rules_timeout_seconds = 300    # время на чтение и принятие правил
  max_attempts = 5               # неверных попыток в пределах одного подключения
  ip_block_after_attempts = 10   # неверных попыток с адреса, переживает переподключение
  ip_block_seconds = 600         # длительность блокировки и срок памяти о неудачах
  attempts_kept_per_account = 30 # сколько неудачных попыток хранится на аккаунт
  min_password_length = 6
  max_password_length = 64
  register_confirm_required = true
  pre_register_premium_enabled = true  # /premium вместо /register для незанятых ников
  allowed_commands = ["login", "l", "register", "reg", "help"]

[sessions]
  enabled = false           # автовход по сессии для пиратских игроков
  timeout_minutes = 10
  require_same_ip = true

[restrictions]
  blindness = true
  slowness = true
  freeze = true
  god_mode = true
  invisible = false
  teleport_to_spawn = false

[twink_protection]
  mode = "disabled"         # disabled | ip | hardware

[messages]
  login_prompt = "§eВведите §a/login <пароль> §eдля входа."
  # все 16 сообщений настраиваются
```

> [!NOTE]
> Значения по умолчанию применяются только к **вновь создаваемому** конфигу. На работающем сервере NeoForge не трогает существующий `goidaauth-common.toml`, поэтому новые настройки после обновления мода нужно вписывать туда вручную.

## Команды

Полный справочник. Доступ разделён на три уровня: **все игроки**, **персонал** (ванильный OP уровня 2, `LEVEL_GAMEMASTERS`) и **консоль** (только консоль сервера, см. ниже).

### Для всех игроков

| Команда | Алиас | Что делает |
|---|---|---|
| `/login <пароль>` | `/l` | Вход в зарегистрированный аккаунт. Не работает, пока адрес заблокирован за перебор. |
| `/register <пароль> <пароль>` | `/reg` | Регистрация. Сначала нужно принять правила. При `register_confirm_required = false` работает и короткая форма `/register <пароль>`. |
| `/rules` | — | Показать правила с первой страницы. |
| `/rules page <n>` | — | Перейти к странице. |
| `/rules categories` | — | Список всех разделов правил. |
| `/rules links` | — | Сайт, Дискорд, Телеграм и остальное, кликабельно. |
| `/acceptrules` | — | Принять правила. Требуется один раз на аккаунт; лицензионного игрока спрашивают точно так же, как пиратского. |
| `/changepassword <старый> <новый> <новый>` | — | Смена собственного пароля. Нужно быть авторизованным. |
| `/premium` → `/premium confirm` | — | Пометить **свой** аккаунт лицензионным. Работает в двух режимах: (1) уже авторизованным (по паролю/сессии) игроком — как раньше; (2) **до регистрации**, вместо `/register`, если ник ещё не занят никем в базе (`pre_register_premium_enabled = true` по умолчанию) — правила всё равно нужно принять первыми. Если ник уже кем-то зарегистрирован (пиратом или премиумом), а вы не вошли — команда откажет, независимо от конфига. Сначала выводит предупреждение: после подтверждения вход возможен только с лицензионного клиента. |
| `/unpremium` → `/unpremium confirm` | — | Вернуть **свой** аккаунт на вход по паролю. Прогресс переносится обратно на офлайн-UUID. |

### Для персонала (OP уровня 2)

**Состояние аккаунтов**

| Команда | Что делает |
|---|---|
| `/premium <игрок>` | Пометить чужой аккаунт лицензионным. Следующее подключение пойдёт через проверку Mojang. |
| `/unpremium <игрок> [пароль]` | Вернуть аккаунт на вход по паролю и перенести прогресс на офлайн-UUID. Без указания пароля аккаунт остаётся без пароля — задайте его через `/setpassword`. |
| `/setpassword <игрок> <пароль>` | Задать пароль аккаунту, у которого его нет (например, бывшему лицензионному). |
| `/forceregister <игрок> <пароль>` | Создать аккаунт за игрока. Правила ему всё равно придётся принять при заходе. |
| `/forcelogin <игрок>` | Пропустить онлайн-игрока через проверку пароля. Барьер правил при этом остаётся. |
| `/unregister <игрок>` | Удалить запись из базы. Игровые данные не трогаются. |
| `/purgeaccount <игрок>` | Полная зачистка — запись в базе, игровые данные, статистика, достижения, права LuckPerms. Создаёт бэкап для отката. |
| `/clearautheffects <игрок>` | Снять слепоту, замедление и невидимость, оставшиеся от блокировки до входа. |

**Расследование**

| Команда | Что делает |
|---|---|
| `/account <игрок>` | Какие аккаунты делят последний IP этого игрока. |
| `/account ip <адрес>` | Какие аккаунты принадлежат адресу. |
| `/accountip <игрок>` | Последний известный адрес игрока. |
| `/multiaccounts <число>` | Все адреса, на которых больше указанного числа аккаунтов. |
| `/attempts [лимит]` | Последние **неудачные** попытки входа по всему серверу. |
| `/attempts recent [лимит]` | То же, явная форма. |
| `/attempts player <ник> [лимит]` | Кто пытался войти в этот аккаунт и не смог — со сводкой по адресам-источникам. |
| `/attempts ip <адрес> [лимит]` | В какие аккаунты ломились с этого адреса — со сводкой по целям. |

> `/account ip` показывает, **кому адрес принадлежит**, а `/attempts ip` — **куда с него ломились**.
> Вместе они отвечают на вопрос «на одном IP несколько аккаунтов — кто из них лез к остальным».

**Перенос данных**

| Команда | Что делает |
|---|---|
| `/transferaccount <откуда> <куда>` | Перенести игровые данные, статистику, достижения, очки скорборда и права LuckPerms между аккаунтами. Источник удаляется, чтобы ничего не задвоилось. |
| `/transferaccount <откуда> <куда> keep_source` | То же, но источник остаётся — возможно дублирование предметов. |
| `/transferaccount backups` | Список бэкапов, доступных для отката. |
| `/transferaccount restore <id>` | Откатить перенос или зачистку. |
| `/importauthme [путь]` | Импорт аккаунтов из базы AuthMe (SQLite). По умолчанию `plugins/AuthMe/authme.db`. |
| `/rules reload` | Перечитать `config/goida_rules.json` без перезапуска. |

### Только из консоли

Доступны **исключительно из консоли сервера** — не оператору, не командному блоку, не функции и не через RCON. Всё здесь уничтожает следы, поэтому намеренно вынесено из-под OP: администратор без доступа к машине не сможет замести собственные следы.

| Команда | Что делает |
|---|---|
| `/goidaauth forget <у_кого> <кого>` | Очищает `last_ip` и `hwid` у **второго** ника, чтобы он перестал появляться в отчёте по общему IP у первого. Затрагивается только второй — порядок аргументов задаёт направление. |
| `/goidaauth forget <у_кого> ip <адрес>` | То же для всех аккаунтов на адресе, кроме первого ника. |
| `/goidaauth attempts clear player <ник>` | Удаляет записи о неудачных попытках входа в аккаунт. |
| `/goidaauth attempts clear ip <адрес>` | Удаляет записи о неудачных попытках с адреса. |

Каждая консольная команда сначала показывает, что именно собирается удалить, и требует явного `confirm` последним аргументом. Учтите: `forget` чистит *историю*, но не подавляет будущие связи — `last_ip` запишется снова при следующем успешном входе этого аккаунта.

**Узлы прав.** Мод публикует `goidaauth.command.login`, `goidaauth.command.register` и `goidaauth.command.premium` через PermissionAPI от NeoForge, чтобы их видели плагины прав, но доступ пока определяется уровнями OP выше — сами узлы ещё не проверяются.


Результат: `build/libs/goidaauth-<версия>.jar` · Требуется Java 21.

## Настройка прокси Velocity

Сервер работает за Velocity? Установите [GoidaAuthVelocity](https://github.com/Yukovsky/GoidaAuthVelocity) на прокси и переключите `database.mode` на `mysql`, чтобы оба использовали одну таблицу `users`. После этого прокси сам решает, в каком режиме — онлайн или офлайн — пускать каждого игрока, ещё до того как соединение дойдёт до бэкенда.
